# DRIV3R Corpus Factory v40 — delayed, host-replayed obstruction memory

**18 November 2026 · Supplemental synthetic corpus · Draft/HOLD PR #1 · not native CyberSand.**

## Research question

The v39 benchmark exposes `input.obstruction` as a current-state feature at every decision, so an observation-only rule suffices. V40 removes that feature. A remote junction transition is instead preserved only as an old, public, event-indexed `REMOTE_OBSTRUCTION` receipt in the model-visible `durable` history. The host subsequently accepts **160 movement actions** before the supervised recovery decision. The latest 64 events, last 64 positions, local legal actions and root geometry are identical for matched CLEAR/BLOCKED cases, yet the optimal first action differs on positive contrasts.

On qualifying positive pairs, CLEAR requires `MOVE_E` and BLOCKED requires `MOVE_S`. **Both are legal in both conditions**, and selecting the opposing action causes at least **two extra actions** under the exact suffix oracle. Removing only the old obstruction receipt makes the input exactly identical between paired cases: a memory-free first-action predictor's theoretical ceiling on balanced **positive** pairs is **50%**, not an empirical model score. Negative controls intentionally retain the same optimal action across phases.

## Causal chronology and oracle qualification

The v32 wrong-material painting history is still generated by accepted host commands. At the beginning of the **final 160 accepted north/root oscillation movements**, the environment changes two remote corridor edges. We reconstruct the host at that exact point using recorded position, predecessor, status, latch and remaining budget; insert the accepted environmental event; then **re-execute all 160 movement commands through host.apply under the changed graph**, checking action acceptance, reported destination, painting correctness and final state against the original prepared history. This is not merely a retroactive event annotation.

For every continuation, the v32 five-target reverse-BFS oracle supplies shortest successful suffixes. Selected actions are applied by the same synthetic host and must complete the objective without residual wrong-material contamination. The obstacle event is never included as a current-state key in the trainer input.

## Negative results and limitations

This remains a synthetic symbolic graph host, **not native CyberSand**. A remote actuator supplies the state change; wrong-material history and the 160-step north/root ageing loop are deliberately scripted. The fixed two-edge junction and single historical event can be solved by symbolic parsing; the scenario does **not** establish general moving-obstacle or multi-event reasoning, nor actual neural competence. No named SLM weights were updated, no native evaluation occurred and no neural inference latency/RSS was measured. Generated shards remain outside Git in the local downloadable source/shard archive, **not immutable Actions artifacts**. v40 supplements v39's dynamic-obstruction question; **v38 remains the broader sequential material-law and memory-recovery benchmark**. No paid model/API/GPU spend or out-of-lane writes.
