## Actual optimisation, timings, evidence

Straight-through Q2 training optimised the actual learnt A/B tensors to reconstruct their original FP32 adapter projections. **60 AdamW updates × 12 modules × 3 source checkpoints = 2,160 actual optimizer steps.** Disjoint random train probes versus held-out Gaussian and sparse probes; this is *not game-labelled training* and no full-LFM outputs were observed. The control includes unchanged FP32 and all unmodified bit-depth variants.

One-thread Torch CPU, 240 resident FP32-decoded adapter-only operations per timed variant; median was ~0.0152 ms (FP32), 0.0154 ms (Q4/Q2/Q1), with noisy p95 ~0.02–0.05 ms. Measured shared process peak RSS **334,612 KiB**. These are **not SLM inference times**, **not tokens/sec**, and show **no kernel acceleration**.

Repeated independent local execution was byte-identical for the per-module JSON, bitpacked adapter payload ZIP and aggregate errors. Timing values differ across runs, as expected. Source script SHA-256 \`0644fee825bfb197fe885e1b5095e0493947b6459c92dca295329b37ce682dd9\`. Reproduce with \`python ql021_real_lora_quant.py --source /path/to/GP350-006-historical-actions-artifact.zip --out /tmp/ql021\` (Python 3.13, Torch CPU, NumPy, safetensors). Weight checkpoints and experimental bitpacked binaries remain outside Git; local evidence is **not** an immutable DRIV3R Actions artifact.
